## B. Oracle specification

### B.1 Independence rules (CA03/CA04/CA18)
1. Expectations derive from: native source at the pins and the explicit corrections in body §4. The mutable Hub contract comments (snapshotted) are **claims to check against source, not an expectation source**. Literals (`789ad395…`, `4d1ad6c9…`, `becaea3f…`) are **re-derived by the evaluator** from native calls on the pinned inputs and compared with the oracle JSON; they are never copied from run output or harness literals. **Never** from `real_c4.py`, `c4_hosted_check.py`, builder verdict summaries or expected-results tables. Those are *subjects* and may be read only to list what they claim.
2. One canonical **oracle JSON** + sha256, posted by a non-builder **before the first run**; evaluator source hash and corpus hash posted with it.
3. The evaluator imports nothing from `real_c4`/`c4_hosted_check` and reads none of their literals (EST-09 static scan). It calls native entrypoints directly and compares loaded module files to pinned git blobs.
4. Where native source is silent, the oracle states in advance an **observe-only predicate**. Silence is never converted into an invented refusal.
5. Oracle edits after any run ⇒ **new oracle version**; prior results retained (append-only). No narrowing after observing results.
6. Developer PASS is never an input. A correct evaluator must say FAIL on a wrong output even when the developer checker says PASS (EST-02/10/12).
7. Per-run values (`decision_id`, `bundle_id`, `generated_at`, `pack_id`, record/bundle/pack hashes) are non-golden; assert *relations* (hash chain continuity, equality across boundaries), not literals.

## C. Minimum mandatory case battery (32 cases = 6 preconditions + 2 controls + 24 adversarial; plus 12 evaluator self-tests)

Verdict per case/profile: **PASS / FAIL / BLOCKED / NOT_EXECUTED / NOT_APPLICABLE**. An unexecuted case is NOT_EXECUTED, never PASS; NOT_APPLICABLE needs a source-backed reason. Any BLOCKED or NOT_EXECUTED mandatory case makes the group non-PASS. "Attempted but unevaluable" (the legacy INCONCLUSIVE) is recorded as **BLOCKED + reason**.

**Case types.** *RI* (required invariant): PASS iff the pre-frozen native refusal/result is observed; FAIL otherwise. *OBS* (observe-only limitation case, also called KLD): the frozen expectation is the **specific native behaviour at the pinned subject** (e.g. "boundary accepted"). **Observed ≠ frozen observation ⇒ FAIL** (frozen subject/environment drift or oracle error — never silently re-baselined; remediation is a new oracle version with old results retained). A match is reported as **`OBSERVED_AS_FROZEN`** in summaries (verdict field PASS only for schema purposes), with `property_demonstrated=false`. **OBS results are tallied separately, are excluded from the Q-A claim gate, and may never be worded as a security PASS.** FAIL also applies where the evaluator/composition claims more than the evidence supports. If Hub#280 or any limitation is later fixed in a successor subject, the OBS expectation changes only via a new frozen oracle version.
