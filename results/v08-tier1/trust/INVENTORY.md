# Worker C (area `trust`) case inventory, committed BEFORE any execution

Assessor: Worker C, fresh AI session, no prior implementation involvement, same organization (independent test design within the organization, NOT independent external qualification).
Designed from: Runtime `engine/registry_selection_authority.py`, `engine/local_authority_effect.py`, `engine/atomic_local_control_plane_executor.py` at `ac247daf`, and ADR EXT-S4-0 sections 3.6, 6.3, 7. No test file was opened before this commit.
Common method: build a store + governed scope + activated selection + provisioned claim through the real writers, then attack durable state or the snapshot/anchor input, and observe the result AT THE EFFECT BOUNDARY (`AtomicLocalControlPlaneExecutor.execute` / `execute_claim_atomic`). DB tampering is done by a second sqlite3 connection (adversary with file write access; triggers dropped where they block). Every refusal case also asserts: 0 rows in `effects`, 0 attempts/receipts, budget `used_effects` unchanged, claim still `issued`, and a typed `selection_refusal` in `control_plane_evidence`. A case is HELD only if the attack was delivered (tamper confirmed by re-reading the DB) AND the typed refusal observed AND a positive control (same claim path succeeds before tamper, or an untampered twin succeeds) proves the path was live. All OS-level work is single-process unless stated; the one multi-process use is the dependency-absence probe (separate interpreter).
