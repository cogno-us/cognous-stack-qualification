# Worker B (atomicity) case inventory, committed BEFORE any execution

Assessor line: Worker B, fresh AI session, no prior implementation involvement, same organization. This is independent test design within the same organization, not independent external qualification.

Designed from: ADR EXT-S4-0 (sections 3.6, 7.1-7.5, 11 AR-04/05/07/08/16/18/26), and the Runtime source `engine/local_authority_effect.py` (`execute_claim_atomic`, seams `_transaction_stage` and `_selection_receipt_evidence`), `engine/registry_selection_authority.py` (`SelectionAuthorityStore._run`, `_stage`, `_verify`, `check_effect`, `HostAnchorFile.advance`), `engine/atomic_local_control_plane_executor.py`. No test file was opened before this commit.

Method for the race/crash cases: every actor is a DISTINCT OS PROCESS (a Python script written for this suite, launched with `subprocess`). Ordering is made deterministic by file barriers and by one process HOLDING the destination write lock at a named stage seam (`_transaction_stage` on the effect path, `SelectionAuthorityStore._stage` on the authority-writer path) while the other process is launched and proven to be waiting (it writes a `before_begin` marker; its `after_begin` timestamp must be later than the holder's commit). Every probe appends `{pid, event, t_ns}` lines to a per-run event log; exit status, stdout and stderr are captured; a missing or malformed probe output is INCONCLUSIVE. Each test records pids, the event sequence, the log-head sequence recorded in the receipt versus the log head after the authority change, and the post-state (counts of effects, attempts, attempt_events, receipts, budget rows used, claim state, `verify_selection_store()` state/cause, anchor head).

Budget plan: 14 executions planned (B-01..B-14), 1 held in reserve for a harness defect; no reruns of a BREACH result.

Will NOT cover: Ed25519 soundness and key custody (out of scope); production anchor custody, power-loss/fsync durability and filesystem-level torn writes beyond SIGKILL and file truncation; withdrawal-race variants (revocation stands in for authority change; withdrawal uses the same lock), multi-host or networked SQLite, stress loops beyond 4 processes, and WAL-file-specific corruption.
