# Testing process

Start with the [bounded comparison process](bounded-comparison.md), adapted from the 15 October 2026 engineering addendum. Complete its configuration and native-evidence checkpoint before finalizing comparison extensions or making prevention claims.

Execution order:

1. Identify the loaded runtime, native receipts, correction/commitment boundaries and observation route.
2. Add only verified instrumentation gaps and calibrate the observer and evaluator.
3. Run D01, then D03; use C07 only when the concurrency contract supports it.
4. Examine D04 separately, retaining its restart, repeat-delivery and observer controls under the same parent scenario.
5. Validate exports, complete each methodology's findings independently, then compare them and publish the bounded findings.

This process is a scoped application of the [execution and evidence contract](../../docs/execution-contract.md). It does not replace the [40-case catalog](../../scenarios/README.md), accept scenarios, select component pins or authorize production. The general agent-pilot repetition proposal and optional future studies are distinct from this comparison's two diagnostic repetitions. No human participation or oversight-effectiveness exercise is included. A conventional-control arm is optional later work.

The [qualification dashboard](../../docs/qualification-dashboard.md) distinguishes static mappings and workflow telemetry from scenario acceptance. The process below is planning material; no new comparison execution is asserted by its publication.
