# Security repairs and residual limits — 16 October 2026

This note records the F5b repairs to qualification tooling and the residual limits left open. It grants no security clearance, release selection or production authorization. Operational HOLD remains in force.

## Repaired

- **Privileged workflow dependencies.** Capture qualification run, Upstream Wiki refresh and Publish qualification dashboard install PyYAML, jsonschema and their transitive dependencies only from `tools/requirements-ci.lock` with `--require-hashes` and binary wheels for CPython 3.12. Pages publication does not persist checkout credentials. Capture and Wiki refresh keep them because their final steps push a branch with the checkout token; those jobs still hold write authority while their own tests run. Hashes bind the downloaded bytes, not the packages' upstream provenance.
- **Local runner source checks.** `tools/prp_openai_evaluation.py`, `tools/run_runtime_authority.py` and `tools/final_source_preflight.py` now call `tools/pristine_checkout.py` before loading external code. A checkout must match the pinned HEAD, show no modified, staged, untracked or ignored files (bytecode included), and have no assume-unchanged or skip-worktree index entries. **Local runners require fresh runner-owned clones.** Do not reuse a working checkout or one another party can write to. These checks do not authenticate a compromised host, exclude concurrent writers or compare every file with a reviewed digest. `tools/run_security_runtime.py` is unchanged because retained F3 evidence binds its hash.

## Residual limits (deferred)

- **Mutable references in read-only reusable workflows (superseded 2026-10-18: Actions are now SHA-pinned; only the image digest remains, see the update below).** Nineteen migrated reusable workflows (`workflow_dispatch`/`workflow_call`, `contents: read`) reference 99 Actions by major tag (`@v4`, `@v5`). The OpenShell image qualification workflow pulls `python:3.12-slim` by tag and records the resolved digest afterwards; it does not enforce a reviewed digest. A moved or compromised upstream tag could therefore alter the code that produces their evidence. Treat their outputs as qualified only for the identities they recorded.
- **Public link checker DNS rebinding.** `tools/check_public_links.py` validates one DNS answer as public and then connects by hostname, so a host that resolves again to a private address can receive the anonymous, bounded HEAD/Range request. This is a local CLI only; run it on hosts with no sensitive internal services in reach.
- **Wiki import has no size budget (superseded 2026-10-18: byte and file caps added, see the update below).** `tools/sync_ai_security_wiki.py` reads and parses upstream Markdown fully in memory without size or count limits. The scheduled refresh is bounded only by its 15-minute job timeout and runner resources; oversized upstream content can make the refresh fail but does not execute upstream code.

## F3 evidence disclosure

The retained F3 source-run summaries (`results/security-runtime-merged-20261016/run-*/source-run-summary.json`) record `qualification_worktree_dirty: true`. This is because the hosted run wrote its untracked outputs inside the qualification checkout before computing that field: `--out results/security-runtime/run-N` and the `--components _components` clones. It does not show that tracked qualification sources changed; `source_hashes` bind the runner, suite and profile bytes.

## Update 2026-10-18 — workflow input validation and supply-chain hardening

Repairs (qualification and orchestrator repositories; no pin, profile, refreeze-log or `V1_PROFILE` value was changed):

- **Workflow inputs are validated before use.** In `v1-validation.yml` the `validation_id` (`^v1-[0-9]{4}-[0-9]{2}-[0-9]{2}-[a-z0-9]+$`) and label (`^[A-Za-z0-9._-]{1,40}$`) are checked from environment variables in the first step of the plan, freeze, provenance-scan and results jobs; the results job (the only one holding write scopes) needs the plan job and runs only when it succeeded. Every `run:` block in every workflow reads values from `env` through quoted variables; a static test (`tests/test_stream_q_hardening.py`) fails if any `run:` block contains an `inputs`, `github.event` or `env` expression. The same validation is repeated in `tools/v1_validation.py aggregate`. Revision inputs of the profile workflows are checked as 40-hex.
- **Aggregation reads control records only from fixed places.** `plan.json` only from `collected/v1v-plan/`, `freeze-verification.json` only from `collected/v1v-freeze/`, `result.json` only at the top level of the other `collected/v1v-*/` directories. A control-named file anywhere else, a symlink, or two results for one (component, os, python) stops the aggregation.
- **Exchange export.** `export_exchange.py` (helpers in `tools/safe_paths.py`; `trajectory_contract.py` is unchanged because retained evidence commits to its bytes) refuses symlinks and non-regular files (lstat walk of the run directory and of every source file), copy with `symlinks=True` after that check, and refuse source or artifact names that are absolute, contain `..`, empty or `.` segments, backslashes or NUL, or resolve outside their root.
- **Third-party Actions are pinned by full commit SHA** (comment shows the release). SHAs were resolved read-only with `git ls-remote` against the Actions repositories at the tag each floating major tag pointed to on 2026-10-18 (checkout v4.2.2, setup-python v5.6.0, upload-artifact v4.6.2, setup-node v4.4.0, download-artifact v4.3.0). `persist-credentials: false` is set on every checkout except three that push with the checkout token (capture run, the results job of `v1-validation.yml`, Wiki refresh); every job has a timeout; every workflow has a top-level `permissions` block.
- **Paid provider pilots.** The Claude and OpenAI pilot workflows install from `tools/requirements-serial.lock` (generated with `uv pip compile --generate-hashes`) with `--require-hashes --only-binary :all:`. Their paid jobs declare `environment: provider-keys`. The owner has configured that environment with a required reviewer and stored the provider keys there as environment secrets (a repository-settings action, not changeable by this work); each live run waits for the reviewer's approval. `prp-openai-evaluation.yml` is deleted from the default branch, and the branch `evaluation/prp-openai-20261015` is already deleted. Repo-level copies of the keys are to be removed by the owner once this change is on `main`.
- **Wiki importer** caps each file at 1 MiB, the total at 8 MiB and the file count at 200, and refuses symlinks. **The weekly refresh opens a pull request and no longer merges it.**
- **Orchestrator.** Overlay candidate refs accept only 40-hex SHAs and default to the current pinned revisions. The attestation verifier bounds depth (32) and node count (20000) iteratively before serialising and treats `RecursionError` as malformed. The registry RPC client refuses redirects and caps response bodies at 8 MiB; the observer caps logs at 2000, fetches one receipt per transaction and enforces an overall deadline (120 s default), each ending as `unknown`, never accepted. The registry snapshot adapter reports `shape_checked_projection` and the checkpoint relation as `unknown` because parent hashes are not verified. Issue #30 (endpoint and transport policy) stays on HOLD: scheme, host and certificate policy remain operational trust.

Residual:

- **Base image digest.** `python:3.12-slim` in the OpenShell image qualification workflow is still pulled by tag; the container registry was not reachable from the environment that made these changes, so no reviewed digest could be resolved. The workflow still records the resolved digest afterwards. Pin a reviewed digest when one can be resolved.
- Repository rulesets, CODEOWNERS, who may dispatch workflows and token defaults are repository settings; without them anyone with write access can still change workflow files.
