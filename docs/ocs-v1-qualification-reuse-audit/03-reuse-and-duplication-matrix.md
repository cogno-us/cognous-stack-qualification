# 03 Reuse and duplication matrix

**Status: documentation-only analysis. Non-authorizing. Draft for Architect review. RELEASE: HOLD. PUBLICATION: HOLD. PRODUCTION: HOLD.**

Nothing here authorizes a migration, approves a pin, selects or activates a record, or changes a qualification verdict. Implementation is not authorized. This is the reuse crosswalk that Constitution CA01 (Reuse Before Build) asks for; CA02 (Minimum Sufficient Implementation) governs how little is then added.

## 1. Classes

| Class | Meaning here |
|---|---|
| REUSE UNCHANGED | Use the existing capability as it is. No edit. |
| EXTEND EXISTING | Add new files or rows that build on it. The existing file is not edited. |
| MISSING — BUILD ONLY IF NECESSARY | Nothing equivalent exists. Build only when the dependency it waits on exists and an independent author needs it. |
| DOMAIN-SPECIFIC — KEEP SEPARATE | Real, but tied to another product or purpose. Do not generalize or fold in. |
| DUPLICATE — CONSOLIDATION CANDIDATE | The same capability exists more than once. The disposition column says whether to consolidate; for V1 the answer is no in every case. |

Each of the 44 capabilities is in exactly one class. Totals: REUSE UNCHANGED 14, EXTEND EXISTING 3, MISSING 9, DOMAIN-SPECIFIC 11, DUPLICATE 7. Machine-readable: [data/capability-matrix.csv](data/capability-matrix.csv).

## 4. Reading the matrix

- **Reuse dominates.** All 17 capabilities classed REUSE UNCHANGED or EXTEND EXISTING live in this repository; none comes from ISSBench. The one ISSBench contribution that survives is a set of property checklists (I06, I07), and those are re-expressed as new cases here, not imported.
- **The nine MISSING rows (Q05, Q07, Q10, Q13, Q15, Q16, Q23, I04, I07) are not all equal.** Q23 (gate catalogue) is a small data file. Q05, Q07, Q10, Q13, Q15 and Q16 are test content that cannot run until the registry consumer, selection destination and claim-carried binding exist; they are authored by an independent author, not by this PR. I04 is optional. I07 is one case family inside QG-09.
- **DUPLICATE rows are a record, not a plan.** Q03, Q29, Q30 and Q31 are inside this repository; I02, I03 and I13 are shared concepts implemented independently in both repositories. Cross-repository consolidation is rejected because it would introduce a dependency, and because the canonical-JSON variants are not byte-equivalent (flags differ: `ensure_ascii`, `allow_nan`, `default=str`), so a merge would change digests.
- **Two near-misses to avoid.** Q21 (MVP `G-00..G-15`) and Q22 (OCS-1/2/3) are both called gates and both are tempting hosts for QG rows. Neither is the right home: they gate a different object and use different verdict words (ACCEPT / REJECT / INCOMPLETE, and PASSING / SKIPPED-WITH-REASON).
